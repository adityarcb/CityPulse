1. Problem Statement

Rapid industrialization, high vehicular density, and localized seasonal temperature inversions in major Indian metropolitan centres (specifically the Indo-Gangetic Basin and Deccan plateau) have created severe public health crises driven by fine ambient particulate matter (PM2.5). Traditional municipal air-quality monitoring frameworks suffer from four critical technological bottlenecks:

  1. High Telemetry Latency (Batch Staleness): Legacy government systems pull sensor readings in coarse batch intervals (12–24 hours), rendering real-time citizen alerts and emergency mitigation impossible during sudden smog inversions.
  2. Single-Node Computational Ceilings: As thousands of low-cost optical IoT particulate sensors and official Continuous Ambient Air Quality Monitoring Stations (CAAQMS) stream continuous telemetry, traditional single-node relational databases suffer from I/O lock contention, dropped packets, and query degradation.
  3. Absence of Spatial Graph Diffusion Modeling: Particulate matter is not isolated to static points; it diffuses through prevailing wind corridors across adjacent metropolitan airsheds (e.g., Punjab to Delhi to Uttar Pradesh). Standard systems analyze cities as isolated scalar values rather than interconnected graph topologies.
  4. Lack of Predictive & Statistical Anomaly Safeguards: Sensor optical chambers suffer from moisture drift, insects, and calibration degradation, generating false spikes. Traditional systems lack distributed machine learning for automated Z-score baseline anomaly filtering and predictive continuous regression forecasting.

2. Objectives of the Project

The objective of CityPulse is to architect, implement, deploy, and benchmark an enterprise-grade distributed cluster computing pipeline for urban atmospheric intelligence. The specific engineering objectives are:

  • High-Throughput Distributed Pub-Sub Logging: Ingest real-time JSON particulate telemetry (PM2.5, temperature, humidity) across 10 canonical Indian metropolitan cities using Apache Kafka topic pollution-readings.
  • Stateful Streaming with Watermarked Tumbling Windows: Implement Apache Spark Structured Streaming using 5-minute tumbling windows and 1-minute event-time watermarking to guarantee fault-tolerant, exactly-once processing with late-data arrival tolerance.
  • High-Performance Distributed Relational Queries: Structure distributed datasets into Spark DataFrames and execute complex multi-table analytical joins and aggregations leveraging the Catalyst Query Optimizer and Tungsten binary execution engine.
  • Atmospheric Diffusion Graph Processing: Formulate an interconnected urban airshed network using Apache Spark GraphX, executing the distributed PageRank algorithm to identify pollution transmission hubs and Connected Components to segment regional airshed corridors.
  • Distributed Machine Learning Pipelines: Develop Spark MLlib pipelines utilizing VectorAssembler to execute continuous PM2.5 Linear Regression forecasting, multi-model severity classification (Random Forest, Decision Tree, Logistic Regression, Naive Bayes), and unsupervised K-Means station archetype clustering.
  • Idiomatic Scala Implementation: Engineer standalone JVM batch jobs utilizing Scala case classes, pattern matching, higher-order functions (map, filter, foldLeft), and RDD lineage transformations packaged via sbt.
  • Living Atmosphere Executive Dashboard: Provide an interactive, responsive control room web interface featuring an HTML5 Canvas particle layer that dynamically modulates particle density and drift speed according to real-time air quality.

6. Implementation / Methodology

The CityPulse platform is engineered across six cohesive operational stages:

6.1 Ingestion Pipeline & Pub-Sub Broker Architecture

IoT monitoring stations and synthetic producers serialize JSON payloads containing metropolitan station attributes and push them over TCP into the pollution-readings Kafka topic. The topic maintains separate partitions allowing concurrent, horizontally scalable consumption across worker nodes.

6.2 Real-Time Stream Ingestion & Statistical Anomaly Filter

A dedicated Python ingestion consumer continuously consumes micro-batches from Kafka. Before committing readings to storage, the consumer executes an in-memory Z-Score Anomaly Detector:

Formula: Z = (x_i - mean_history) / std_history
Where mean and std are computed over prior historical baseline readings for that specific city. To prevent false alarms, the current event is excluded from baseline statistics, and an INSUFFICIENT_DATA guard requires N ≥ 5 prior readings.

6.3 Spark Structured Streaming & Watermarked Tumbling Windows

The spark_jobs/kafka_stream.py job binds to Kafka using spark.readStream. It enforces a strict schema, converts string timestamps to distributed event-time columns, applies a 1-minute watermark to discard out-of-order records older than 60 seconds, and aggregates records into 5-minute tumbling windows (avg_pm25, max_pm25, reading_count).

6.4 Distributed GraphX Atmospheric Diffusion Modeling

The 10 canonical cities form vertices in an atmospheric multigraph (V = 10). Edges (E) are dynamically established between city pairs whose geographical Haversine distance is within the atmospheric proximity threshold (d ≤ 650 km):

Haversine Distance Formula: d = 2R · atan2(sqrt(a), sqrt(1-a))
Where a = sin²(Δlat/2) + cos(lat1)·cos(lat2)·sin²(Δlon/2).
Edge weights represent atmospheric mass transport: W_ij = (1000 / d) · (1 + PM2.5 / 100).
The distributed PageRank algorithm converges after iterative message passing to reveal which cities act as central pollution accumulation sinks.

6.5 Spark MLlib Distributed Feature Pipeline

The machine learning laboratory extracts cyclical temporal features (hour_of_day, day_of_week), ambient temperature, and prior lag values (pm25_lag1). Features are vectorized via VectorAssembler into feature tensors and passed into:

  • Linear Regression: Continuous PM2.5 concentration forecasting (R² = 0.614, RMSE = 34.95 µg/m³).
  • Severity Classifier Benchmark: Evaluates Random Forest, Decision Tree, Logistic Regression, and Gaussian Naive Bayes.
  • Unsupervised K-Means: Segments stations into 3 environmental clusters (Clean Plateau, Moderate Industrial, Severe Smog Belt).

6.6 Single Source of Truth Relational Architecture

To eliminate dashboard discrepancy bugs, all KPI cards across all views pull strictly from the PostgreSQL view city_latest. This guarantees the single source of truth invariant:

Guaranteed Mathematical Invariant
Cities NORMAL + Cities HIGH + Cities CRITICAL = Total Monitored Cities (10)

7. Project Architecture & Flowchart

The CityPulse platform is engineered as a decoupled, event-driven distributed streaming system. Telemetry flows continuously from edge optical sensors and official CAAQMS stations through high-throughput Kafka partitions, undergoes statistical anomaly screening, streams through Apache Spark Structured Streaming with watermarking, executes distributed GraphX diffusion and MLlib inference, and materializes into PostgreSQL for real-time visualization.

Figure 7.1: CityPulse End-to-End Distributed Stream Processing, Machine Learning, and Environmental Intelligence Architecture Flowchart.

7.1 Architectural Execution Workflow

  1. Telemetry Generation & Pub-Sub Broker: IoT stations and live CPCB poller generate microsecond-timestamped JSON payloads and publish them to partitioned Kafka broker topic pollution-readings.
  2. Dual-Stream Ingestion Path:
    • Stream A (Fast Alerting & Anomaly): Ingestion worker reads micro-batches, evaluates dynamic Z-scores against historical baselines, and commits validated readings to PostgreSQL.
    • Stream B (Distributed Tumbling Windows): Spark Structured Streaming applies 1-minute watermarking to handle network delay and computes tumbling 5-minute averages.
  3. Distributed GraphX Diffusion Modeling: Cities are dynamically mapped into a geographical airshed network. Mass transport edge weights model cross-border pollution drift, and PageRank discovers dominant atmospheric accumulation sinks.
  4. Spark MLlib Predictive Inference: Feature tensors are generated via VectorAssembler to feed Linear Regression continuous forecasting, multi-model classifiers (Random Forest, Decision Tree, Logistic Regression), and unsupervised K-Means station clusters.
  5. Single Source of Truth Serving: All UI widgets query transactional view city_latest, strictly preserving the mathematical invariant NORMAL + HIGH + CRITICAL = 10.
